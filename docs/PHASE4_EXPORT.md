# Phase 4 — 투명 PNG 애니메이션 프레임 내보내기

## 사용 방법

1. 애니메이션 타임라인에서 키가 하나 이상 있는 클립을 선택합니다.
2. `☰` → **애니메이션 PNG 프레임 내보내기**를 누릅니다.
3. 256, 512, 1024 정사각형 출력 크기를 고르고 파일 선택기에서 ZIP 저장 위치를 정합니다.
4. ZIP 안의 `frames/frame_0000.png`부터 순서대로 사용합니다. `manifest.json`에 클립명, FPS, 프레임 수, 크기와 알파 여부가 기록됩니다.

내보내기는 인터넷 연결 없이 동작합니다. PNG는 투명 배경이며 PNG 시퀀스와 메타데이터만 포함합니다. GIF/영상 인코딩, 오디오, 루프 경계 프레임 추가, 사용자 지정 종횡비는 지원하지 않습니다.

## 범위와 제한

- 선택 클립의 `0..durationFrames-1` 프레임을 저장하고 기존 AnimationEngine, ParameterEngine, RigEvaluator 평가 결과를 사용합니다.
- 레이어 순서, 표시 상태, 파츠 투명도, 메쉬 UV, 회전/워프 계층이 프레임에 반영됩니다.
- 모든 프레임의 합집합 범위에 맞춰 일정한 확대율을 계산하므로 애니메이션 중 모델이 움직여도 프레임마다 크기가 흔들리지 않습니다.
- 삼각형 텍스처 매핑에는 Android Canvas 소프트웨어 래스터화를 사용합니다. OpenGL 캔버스와 색공간/필터링이 완전히 같다고 보장하지 않습니다.
- 최대 300프레임, 프레임 전체의 렌더 비용 128,000,000픽셀, 프레임당 1024×1024입니다. 제한을 넘으면 크기를 줄이거나 클립 길이를 줄여야 합니다.
- 한 번에 프레임 하나만 렌더링 비트맵으로 보유합니다. 사용 중인 입력 텍스처 비트맵은 ZIP 기록 동안 캐시합니다.
- 파일 선택기 제공자의 출력은 원자적으로 교체되지 않을 수 있습니다. 저장이 중단되면 해당 위치의 부분 ZIP을 삭제하고 다시 내보내세요.

## 검증

`AnimationSequenceExporterDeviceTest`는 에뮬레이터에서 ZIP/manifest/프레임 개수, PNG 크기와 투명 배경, 애니메이션에 따른 실루엣 면적 변화를 확인합니다. 예산을 넘는 크기는 ZIP 바이트를 쓰기 전에 거부하는지 확인합니다. `AnimationDeviceTest`는 편집 화면의 내보내기 대화상자 경로를 확인합니다.

자동화 검증은 실제 PNG 파일 선택기, 여러 OEM의 파일 공급자, 장시간/저사양 기기의 성능·메모리 사용량을 대신하지 않습니다. 알파 영역 자동 메쉬는 별도 후속 PR에서 다룹니다([설계 및 범위](PHASE4_MESH.md)). PSD, GIF/영상, 실제 기기 성능 계측은 아직 미구현입니다.
